Engineering decisions

FundedScope as a case study.

A short view of the problem, architecture, technical decisions, trade-offs, and next improvements behind the product.

Problem

Traders lacked a single platform to compare prop firms and brokers using transparent data, reviews, spreads, account rules, and market context.

Solution

Designed and built a full-stack SaaS platform with authentication, PostgreSQL-backed data, REST APIs, SEO optimisation, comparison tools, and responsive UI.

Challenges

  • Structuring broker and prop firm data for comparison.
  • Designing protected routes and authentication flows.
  • Keeping SEO pages useful while supporting dynamic data.
  • Deploying across frontend, backend, database, and custom domain.
Next.js FrontendResponsive UI, SEO pages, comparison screens
REST APINode.js and Express routes for product data
PostgreSQLSupabase database for brokers and prop firms
AuthenticationSupabase auth, protected routes, user sessions

Key Decisions

  • Used PostgreSQL to keep broker and prop firm data structured.
  • Used Supabase to speed up authentication and database workflows.
  • Built comparison features around reusable data fields.

Trade-offs

  • Prioritised clear public comparison pages before deeper user personalisation.
  • Started with manual QA while expanding towards automated tests.
  • Kept the first architecture simple so the product can ship and improve.

Next Version

  • Add automated unit and integration tests around APIs.
  • Add CI/CD checks before deployment.
  • Improve personalised recommendations and dashboard depth.

Testing

  • Manual QA across desktop and mobile views.
  • Authentication and protected route checks.
  • Next step: unit, integration, and end-to-end testing.

Performance

  • Mobile responsive interface.
  • SEO optimised pages.
  • Fast public page navigation.
  • Lighthouse score to be measured before publishing claims.
